Ten steps

  1. Launch one instance.

    Amazon Linux 2023 in a private subnet, wrapped in an Auto Scaling group of exactly one, IMDSv2 required. The ASG is your availability story: if the instance dies, AWS replaces it without a human.

    aws autoscaling create-auto-scaling-group --region us-gov-west-1 \
  --auto-scaling-group-name consus-local-log \
  --min-size 1 --max-size 1 --desired-capacity 1 \
  --launch-template LaunchTemplateName=consus-local-log \
  --vpc-zone-identifier subnet-PRIVATE

  2. Install the binary — and prove it.

    Download the pinned release and verify the checksum. If your review process demands more, rebuild it from source with the same Go version and compare hashes: the builds are byte-for-byte reproducible.

    curl -LO https://github.com/consusindustries/consus-local-log/releases/download/v1.0.0/consus-local-log_v1.0.0_linux_amd64
curl -LO https://github.com/consusindustries/consus-local-log/releases/download/v1.0.0/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
sudo install -m 0755 consus-local-log_v1.0.0_linux_amd64 /usr/local/bin/consus-local-log

  3. Give the log its own encrypted disk.

    A dedicated gp3 volume, encrypted with your KMS key (account-default EBS encryption covers this), mounted where the proxy expects it. Size for 50–100 MB per heavy user per day before compression.

    sudo mkfs.xfs /dev/nvme1n1
echo "UUID=$(sudo blkid -s UUID -o value /dev/nvme1n1) /var/log/consus xfs defaults,noatime 0 2" | sudo tee -a /etc/fstab
sudo mkdir -p /var/log/consus && sudo mount -a

  4. Run it as a service.

    The unit in deploy/systemd/ creates the log directory with the right owner and modes, strips every capability the proxy never uses, and sets the stop timeout so a graceful shutdown outlasts your longest stream.

    sudo useradd --system --shell /usr/sbin/nologin consuslog
sudo cp deploy/systemd/consus-local-log.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now consus-local-log

  5. Put your TLS in front.

    An internal Application Load Balancer with a certificate from ACM. Target the instance on port 4000; health-check /healthz — it answers instantly even while the upstream is down, so it never flaps during an outage.

  6. Name it yours.

    A Route 53 private-zone record — llm.internal.example.com — pointing at the ALB. Your domain, deliberately: everything inside the boundary is yours, and the name should say so.

  7. Open exactly one door each way.

    Security group: inbound 4000 from the ALB's security group only; outbound 443 so the proxy can reach the gateway through your NAT path. The instance needs direct outbound 443 — no corporate CONNECT proxy in the middle.

  8. Ship the log.

    The CloudWatch agent tails the directory. The instance role carries CloudWatchAgentServerPolicy — the only IAM in this whole deployment, and it belongs to the agent, not the proxy. Prefer Splunk or Fluent Bit? The log is plain JSONL; use deploy/fluent-bit/. Ship the service's stderr from journald too — it carries the why behind any logging failure.

    { "logs": { "logs_collected": { "files": { "collect_list": [
  { "file_path": "/var/log/consus/*.jsonl",
    "log_group_name": "/consus/local-log",
    "log_stream_name": "{instance_id}", "timezone": "UTC" }
] } } } }

  9. Alarm on silence.

    From deploy/alerts.md: a metric filter on dropped > 0 (entries lost — page), an absence alarm when no lines arrive during working hours, and disk at 80%. For this product, logging-stopped is a worse failure than proxy-down.

  10. Lock the exits.

    Host access through SSM Session Manager only — no SSH keys. Nightly archive to your own bucket. When the pilot holds, make it mandatory: outbound 443 to api.consus.io allowed from this instance alone, REJECT everywhere else, so stragglers fail fast instead of hanging.

    15 0 * * * aws s3 sync /var/log/consus/ s3://YOUR-BUCKET/consus-local-log/ --exclude "$(date -u +\%F).jsonl"

Tell your people one thing

Keys, tools, SDKs — unchanged. One setting moves:

export OPENAI_BASE_URL=https://llm.internal.example.com/v1

Verify it, end to end

# 1. The proxy is up and can see the gateway
curl -s https://llm.internal.example.com/healthz
   {"upstream_ok":true,"log_misses":0,"uptime_s":42}

# 2. One real request through it
curl -s https://llm.internal.example.com/v1/models -H "x-api-key: $YOUR_KEY"

# 3. The line is on disk — and in your SIEM moments later
jq -c '{ts, path, status, consus_key_id}' /var/log/consus/$(date -u +%F).jsonl | tail -1

What this never needs

  • No IAM role for the proxy. The binary makes no AWS calls. The only credentialed component is your log shipper.
  • No inbound from the internet. Private subnet, internal ALB, SSM for humans. Nothing listens publicly.
  • No agent, no callback, no telemetry. The proxy's only outbound connection is the traffic you send through it.
  • No partition surprises. GovCloud friction usually comes from software assuming commercial ARNs and endpoints. This binary has neither — its entire cloud surface is a Linux process, a disk, and outbound 443.
