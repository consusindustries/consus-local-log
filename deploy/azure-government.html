Ten steps

  1. Launch one VM.

    Ubuntu 24.04 LTS in a private subnet (no public IP), in a Virtual Machine Scale Set with capacity one — usgovvirginia or your region. The scale set is your availability story: if the VM dies, Azure replaces it without a human.

    az vmss create --resource-group consus --name consus-local-log \
  --image Ubuntu2404 --instance-count 1 --orchestration-mode Flexible \
  --vnet-name corp-vnet --subnet private --public-ip-address ""

  2. Install the binary — and prove it.

    Download the pinned release and verify the checksum. If your review process demands more, rebuild it from source with the same Go version and compare hashes: the builds are byte-for-byte reproducible.

    curl -LO https://github.com/consus-io/consus-local-log/releases/download/v1.0.0/consus-local-log_v1.0.0_linux_amd64
curl -LO https://github.com/consus-io/consus-local-log/releases/download/v1.0.0/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
sudo install -m 0755 consus-local-log_v1.0.0_linux_amd64 /usr/local/bin/consus-local-log

  3. Give the log its own encrypted disk.

    A dedicated managed data disk — server-side encryption is on by default; use your own key via a disk encryption set if policy requires. Size for 50–100 MB per heavy user per day before compression.

    sudo mkfs.xfs /dev/disk/azure/scsi1/lun0
echo "UUID=$(sudo blkid -s UUID -o value /dev/disk/azure/scsi1/lun0) /var/log/consus xfs defaults,noatime 0 2" | sudo tee -a /etc/fstab
sudo mkdir -p /var/log/consus && sudo mount -a

  4. Run it as a service.

    The unit in deploy/systemd/ creates the log directory with the right owner and modes, strips every capability the proxy never uses, and sets the stop timeout so a graceful shutdown outlasts your longest stream.

    sudo useradd --system --shell /usr/sbin/nologin consuslog
sudo cp deploy/systemd/consus-local-log.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now consus-local-log

  5. Put your TLS in front.

    An internal Application Gateway with a certificate from Key Vault. Backend pool: the VM on port 4000; health probe /healthz — it answers instantly even while the upstream is down, so it never flaps during an outage.

  6. Name it yours.

    A Private DNS zone record — llm.internal.example.com — pointing at the gateway's private frontend. Your domain, deliberately: everything inside the boundary is yours, and the name should say so.

  7. Open exactly one door each way.

    NSG: inbound 4000 from the Application Gateway subnet only; outbound 443 through your NAT gateway so the proxy can reach the Consus gateway. The VM needs direct outbound 443 — no corporate CONNECT proxy in the middle.

  8. Ship the log.

    Azure Monitor Agent with a Data Collection Rule: a Custom Text Log source on /var/log/consus/*.jsonl into a Log Analytics table your Sentinel workspace reads. AMA authenticates with managed identity — the only identity in this whole deployment, and it belongs to the agent, not the proxy. Prefer Splunk or Fluent Bit? The log is plain JSONL; use deploy/fluent-bit/. Ship the service's stderr from journald too — it carries the why behind any logging failure.

  9. Alarm on silence.

    Scheduled KQL alerts from deploy/alerts.md: any line with dropped > 0 (entries lost — page), an absence alert when no lines arrive during working hours, and disk at 80%. For this product, logging-stopped is a worse failure than proxy-down.

    ConsusLocalLog_CL | where dropped_d > 0
ConsusLocalLog_CL | summarize last=max(TimeGenerated) | where last < ago(15m)

  10. Lock the exits.

    Host access through Azure Bastion only — no public SSH. Nightly archive to your own storage account. When the pilot holds, make it mandatory: an Azure Firewall application rule allowing api.consus.io:443 from this subnet alone, denied everywhere else, so stragglers fail fast instead of hanging.

    15 0 * * * azcopy sync /var/log/consus "https://YOURACCOUNT.blob.core.usgovcloudapi.net/consus-local-log" --exclude-pattern "$(date -u +\%F).jsonl"

Tell your people one thing

Keys, tools, SDKs — unchanged. One setting moves:

export OPENAI_BASE_URL=https://llm.internal.example.com/v1

Verify it, end to end

# 1. The proxy is up and can see the gateway
curl -s https://llm.internal.example.com/healthz
   {"upstream_ok":true,"log_misses":0,"uptime_s":42}

# 2. One real request through it
curl -s https://llm.internal.example.com/v1/models -H "x-api-key: $YOUR_KEY"

# 3. The line is on disk — and in Sentinel moments later
jq -c '{ts, path, status, consus_key_id}' /var/log/consus/$(date -u +%F).jsonl | tail -1

What this never needs

  • No managed identity for the proxy. The binary makes no Azure calls. The only credentialed component is your log shipper.
  • No inbound from the internet. Private subnet, internal gateway, Bastion for humans. Nothing listens publicly.
  • No agent, no callback, no telemetry. The proxy's only outbound connection is the traffic you send through it.
  • No sovereign-cloud surprises. Government-cloud friction usually comes from software assuming commercial endpoints. This binary assumes none — its entire cloud surface is a Linux process, a disk, and outbound 443.
